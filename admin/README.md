# اتاق فرمان ابری رسانه میم

## ظاهر و مسیرها

- صفحهٔ `admin/` شامل ورود با نام کاربری و بازیابی رمز است.
- داشبورد RTL واکنش‌گرا با تم مشکی‌ـ‌طلایی سایت اصلی شامل منوی کناری، آمار واقعی محتوا، کارت پروژه با تصویر، اطلاعات تماس و امنیت حساب است.
- مسیرها نسبی‌اند و در GitHub Pages زیر `/TEST/` کار می‌کنند.
- صفحهٔ مرجع معرفی‌شده هنگام بررسی HTTP 403 داشت؛ این ظاهر یک طراحی اختصاصی است، نه بازسازی تأییدشدهٔ آن صفحه.

## Supabase

با انتخاب مالک، پروژهٔ موجود `ideh-pardazan` (`jmpwryddrxmuwzmbmhsb`) استفاده شده است. ساخت پروژهٔ جدا به محدودیت تعداد پروژه‌های رایگان برخورد کرد. جدول‌های IDEA تغییر نکرده‌اند.

جدول‌ها و توابع مستقل:

- `miim_content`: تک‌ردیف `main`، محتوای عمومی JSON، زمان ذخیره و نسخهٔ افزایشی.
- `miim_admins`: فهرست ایمیل مدیران؛ فاقد دسترسی عمومی یا دسترسی تغییر برای کاربران سایت.
- `miim_is_admin()`: بررسی سمت دیتابیس با `auth.uid()`، ایمیل واقعی `auth.users` و تأیید ایمیل؛ نه متادیتای قابل‌تغییر توسط کاربر.
- خواندن محتوا عمومی است. فقط مدیر تأییدشده حق UPDATE ستون data را دارد. INSERT/DELETE عمومی مجاز نیست.
- ایمیل اولیهٔ مدیر: `resane.miim@gmail.com`.
- شرط `revision` مانع بازنویسی بی‌خبرٔ ذخیرهٔ مرورگر دیگر می‌شود. در تعارض، پیش‌نویس حفظ می‌شود؛ کاربر با تأیید خود تازه‌سازی می‌کند.
- هش رمز/کلید خصوصی در محتوای عمومی ذخیره نمی‌شود. `authHash` قبل از خروجی و ارسال حذف و در DB نیز ممنوع شده است.
- فقط کلید **publishable** در کد مرورگر است. هرگز service-role یا secret key را در این ریپوزیتوری نگذارید.

فایل migration در `supabase/migrations/` و seed اولیه در `supabase/seed.sql` است. این فایل‌ها **روی پروژهٔ فعلی اعمال شده‌اند**؛ دوباره اجرا نکنید. seed فقط چهار نمونه‌کار را ذخیره می‌کند. سایر بخش‌ها از `data.json` پایه خوانده می‌شوند؛ اولین انتشار، سند کامل را ذخیره می‌کند.

## ورود مدیر

- نام کاربری مدیر `mojtaba` است. در لایهٔ اتصال Auth، این شناسه به حساب موجود `resane.miim@gmail.com` نگاشت می‌شود. ورود با ایمیل نیز برای سازگاری و تأیید رمز فعلی پشتیبانی می‌شود.
- رمز درخواستی مالک فقط سمت دیتابیس Auth به صورت bcrypt تنظیم شده و هیچ نسخه‌ای از آن در Git، کد مرورگر، مستندات یا دادهٔ عمومی وجود ندارد. حساب مدیر موجود با تأیید مدیریتی فعال شده است.
- نگاشت نام کاربری، مرز امنیتی نیست؛ رمز واقعی توسط Supabase Auth و مجوز مدیریت توسط RLS سرور بررسی می‌شود.
- برای بازیابی، می‌توان نام کاربری `mojtaba` را وارد کرد؛ لینک به ایمیل مدیر ارسال می‌شود.
- برای تغییر رمز، بخش «امنیت حساب» ابتدا رمز فعلی را با Auth دوباره بررسی می‌کند.

مسیر `https://miimdev.github.io/TEST/admin/` به allowlist تغییر مسیر Auth اضافه شده است. `site_url` و سیاست‌های ورود/ثبت‌نام پروژهٔ IDEA تغییر داده نشده‌اند. لینک تأیید/بازیابی به آدرس تولید برمی‌گردد، نه آدرس پیش‌نمایش. برای دامنهٔ سفارشی، allowlist و `redirectTo` در `lib/cloud.js` را به‌روزرسانی کنید.

ارسال ایمیل تابع محدودیت نرخ و تنظیمات SMTP همین پروژه است. اگر Supabase اجازهٔ ارسال به این ایمیل را نداد، SMTP مناسب را در داشبورد Supabase پیکربندی کنید؛ تأیید ایمیل را خاموش نکنید. تغییر رمز حساب فقط با درخواست صریح مالک و خارج از فایل‌های ریپوزیتوری انجام شده است؛ اعتبارسنجی رمز مرورگر هرگز با مقایسهٔ محلی انجام نمی‌شود.

## ذخیره و انتشار

«ذخیره و انتشار» محتوا را مستقیماً در Supabase ذخیره می‌کند. دیگر جایگزینی دستی `data.json` لازم نیست. صفحهٔ عمومی در هر بار بارگذاری دادهٔ ابری را می‌خواند؛ اگر اتصال قطع باشد، نسخهٔ `data.json` ریپوزیتوری را نمایش می‌دهد. پیش‌نویس‌های قدیمی localStorage هیچ‌وقت دادهٔ ابری را override نمی‌کنند. برای به‌روزرسانی تب عمومی باز، آن را بازخوانی کنید (تب‌های همین مرورگر از BroadcastChannel نیز مطلع می‌شوند).

«دریافت نسخهٔ پشتیبان» JSON فرم را بدون ذخیره/انتشار دانلود می‌کند. انتشار فقط وقتی موفق اعلام می‌شود که سرور ذخیره را تأیید کند. در قطع اتصال، خطای دسترسی یا تعارض نسخه، پیش‌نویس نگه داشته می‌شود. ویرایش تصاویر و افزودن/حذف پروژه هنوز در رابط وجود ندارد.

## توسعه و تست

```sh
npm ci
npm run build:cloud
npm test
python3 -m http.server 8000 --bind 0.0.0.0
# ترمینال دیگر:
npx playwright install chromium
npm run test:browser
```

باندل `vendor/miim-cloud.js` عمداً در Git است تا GitHub Pages بدون build و بدون CDN کار کند. تغییرات `lib/cloud.js` باید با دستور build بالا دوباره باندل شوند. فایل license کنار باندل نگه داشته شود.

تست مرورگر از API شبیه‌سازی‌شدهٔ Supabase استفاده می‌کند: هیچ ایمیل، کاربر آزمایشی یا تغییر محتوای واقعی ایجاد نمی‌شود. ورود از دکمهٔ هدر، نگاشت نام کاربری/مجوز مدیر، انتشار موفق و ناموفق، تعارض نسخه، بازیابی/تغییر رمز، خروج، نمایش عمومی و عرض موبایل تست می‌شوند. اعتبارسنجی زندهٔ دیتابیس جدا با connector انجام شد (RLS، دسترسی ستون‌ها و جلوگیری از UPDATE کاربر بدون عضویت).

## جلوگیری از کش نسخهٔ قبلی

بعد از هر تغییر CSS/JS، دستور `npm run build` را اجرا کنید. `scripts/version-assets.cjs` آدرس فایل‌ها را با هش محتوا نسخه‌دار می‌کند و لینک ورود در هدر را نیز به نسخهٔ فعلی HTML پنل وصل می‌کند. بنابراین نسخهٔ جدید HTML با CSS/JS قدیمی مرورگر ترکیب نمی‌شود. تغییر فایل‌های وابسته بدون اجرای دوبارهٔ این دستور باعث شکست تست `assets.test.cjs` می‌شود.

## حرکت و جلوه‌های بصری

`admin/motion.js` ذرات نور Canvas و پارالاکس ناحیهٔ لوگو را مدیریت می‌کند. حلقه‌های مداری، درخشش دکمه، شناوری لوگو و کارت‌ها با CSS اجرا می‌شوند. انیمیشن تأیید ورود فقط پس از بررسی موفق حساب و دسترسی مدیر نمایش داده می‌شود. رندر ذرات هنگام مخفی‌شدن پنل یا تب متوقف می‌شود؛ تمام حرکت‌های تزئینی تابع `prefers-reduced-motion` هستند. لینک هدر، HTML و وابستگی‌های پنل با هش محتوا نسخه‌دار می‌شوند.
